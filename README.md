# 澎湃通行密钥解锁

一个面向小米 HyperOS 的模块，用来恢复 AOSP 凭据管理器的通行密钥选择体验，并修复小米对第三方凭据提供方和扫码跨设备流程的限制。

## 引入

在部分小米系统中，原生 Android 本身已经提供了完整的凭据管理器和第三方通行密钥支持，但系统会在设置和运行时流程中优先接管到小米密码管理：

- 在设置页面隐藏 Bitwarden、Google 密码管理工具等第三方提供方的启用开关；
- 创建或登录通行密钥时，界面被替换成小米自己的密码管家页面，无法选择保存其它位置；
- 电脑扫码创建或登录时，远程请求被小米 FIDO 流程独占。

这会导致“系统支持第三方提供方”变成“实际上只能使用小米密码管理”。本模块的目标是尽量恢复系统原本的 AOSP 选择器，让用户在创建和使用通行密钥时自行选择来源。

## 和另一个相似模块的区别

本模块会将小米写死的流程重定向至 AOSP 界面，而另一个模块会重定向至 GMS 界面。这两个页面本身区别不大，但本模块摆脱了对 GMS 的依赖。你不需要打开谷歌基础服务就能使用本模块带来的解锁第三方（如 Bitwarden）通行密钥的功能。扫码连接第三方设备时也不需要对方设备能够访问谷歌服务器。

## 原理

模块按照功能分别运行在相关应用进程中：

1. 在系统设置进程中，恢复第三方通行密钥提供方的开关。
2. 在小米 FIDO 进程中，保留电脑扫码所需的 Hybrid FIDO 通信和回调协议，但把已经解析出的创建/登录请求交给 Android 凭据管理器。这样扫码仍由小米流程负责连接电脑和认证，实际选择凭据来源时可以进入 AOSP 选择器选择第三方来源，完成后再把结果转回去。
3. 在 AOSP 凭据管理器进程中，将小米定制的创建页、登录页和相关选择页重定向到 AOSP 的页面。
4. 本地应用创建或登录时，应出现 AOSP 风格的凭据选择器；扫码连接其它设备时，连接仍由小米 Hybrid FIDO 完成，但保存和选择会转发给给 AOSP 界面。
5. 可选地在 Google Play 服务进程中伪装 Hybrid 请求的调用方身份，用于解决 Google 密码管理工具拒绝 `com.fido.asm` 请求的兼容性问题。这个兼容层可能有安全风险，因此默认不勾选作用域。

模块本身不充当密码管理器，也不保存通行密钥私钥；具体密钥仍由用户选择的凭据提供方创建、保存和签名。模块只在相关进程的请求传递和UI环节工作。

## 作用域

### 推荐作用域

以下三个作用域组成主功能，建议全部启用：

| 应用 | 作用 |
| --- | --- |
| 设置 `com.android.settings` | 恢复设置中第三方凭据提供方的显示、开关和选择入口。 |
| MI FIDO `com.fido.asm` | 转发扫码连接其它设备后的流程，防止被交给小米密码管家。 |
| 凭据管理器 `com.android.credentialmanager` | 将小米的创建/登录界面恢复为 AOSP 界面，提供保存位置和凭据来源选择。 |

### 可选作用域（自行勾选）

| 应用 | 什么时候启用 | 说明 |
| --- | --- | --- |
| 密码 `com.miui.passwords` | 需要在不开启云同步的情况下使用小米的通行密钥时 | 一般不用勾，应该没什么人用小米的密码管理吧（） |
| Google Play 服务 `com.google.android.gms` | 电脑等的扫码连接需要使用来自 Google 密码管理工具的通行密钥时 | 远程扫码认证会由小米FIDO组件转发，而谷歌默认不将其视为可信特权应用，因此需要一个伪装 |

不需要为了使用 Bitwarden、Edge 或其他第三方提供方而勾选 `com.miui.passwords` 或 `com.google.android.gms`；只有对应场景确实需要时，再单独增加可选作用域。

## 使用建议

1. 在模块管理器中启用推荐作用域，强制停止相关应用或重启系统，使作用域变更生效。
2. 到系统设置->更多设置->语言与输入法->密码和账号确认第三方提供方开关已经出现并打开。
3. 扫码连接其它设备时，请通过系统相机（你可能需要在先相机设置里打开二维码扫描的功能）或系统的AI扫描/小爱扫一扫进行，模块会拦截向小米密码管理发出的请求并转发。

## 故障排除

如果某个提供方已在设置启用但不在列表中显示，请检查系统电池优化是否压死了后台。如 Bitwarden，HyperOS 上需要设置后台无限制才能出现在列表中。

## 已知边界

- 本项目针对小米澎湃 OS 的相关实现，类名、系统版本和厂商改动可能导致某些 hook 失效；代码使用 DexKit 尽量减少对混淆名称的依赖，但不能保证跨所有版本永久兼容。
- 主功能依赖 Android 14 及以上的系统凭据管理器和 Hybrid Credential 流程；较旧系统可能只能加载部分兼容逻辑。
- 模块当前只打包 `arm64-v8a`，适合目标小米设备。
- Google 密码管理工具是否出现还会受到浏览器信任关系、请求来源和 Google 自身策略影响；可选 GMS 兼容层不能保证所有账号和应用场景都显示它。
